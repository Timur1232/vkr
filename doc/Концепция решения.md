# Концепция решения

Разрабатываемая система представляет собой локальную распределённую систему контроля версий, ориентированную на не-технических пользователей. Она должна сочетать идеи Git (распределенность, нелинейная история) с упрощённой концептуальной моделью, подобной Gitless.

Система предназначается для:

- людей творческих профессий;
- одиночных разработчиков или маленьких команд (2-3 человека);
- обычных пользователей.

Люди творческих профессий включают: дизайнеров, писателей, художников, фотографов. Они работают с большими объёмами файлов, часто экспериментируют, создают несколько вариантов одного и того же проекта. Им важно легко возвращаться к предыдущим версиям, сравнивать варианты, синхронизировать работу между устройствами. При этом они не хотят изучать сложные команды и концепции.

Обычные пользователи - это люди, которые ведут заметки, хранят личные документы, фотографии и хотят иметь резервные копии и историю изменений на нескольких устройствах (ноутбук, телефон, планшет). Для них важны простота, автоматизация и понятный интерфейс.

**Сохранение сделанных пользователем изменений и возвращение к прошлым состояниям**. В этом заключается основной принцип историчности систем контроля версий. Пользователь должен иметь возможность сохранять сделанные им во время сессии изменения и в любой момент безопасно откатить состояние проекта к определенному состоянию.

**Нелинейность истории**. Пользователь при желании может создать ответвление своего репозитория в определенном месте истории, например, для экспериментов с проектом. Ветки должны быть изолированными друг от друга, чтобы не создавать конфликтов состояния. После окончания работы в созданной ветке пользователь должен иметь возможность выполнить слияние.

**Автоматическое разрешение и локализация конфликтов**. При возникновении конфликта во время слияния система не останавливает процесс, а создает локализированные ветки для конфликтующих состояний файла (суперпозиция файла). Затем пользователь через интуитивный интерфейс может выбрать нужное состояние или разрешить конфликт через интерактивный интерфейс для выбора нужных фрагментов.

**Простой и дружелюбный интерфейс**. Предполагается графический интерфейс с минимальным количеством кнопок и понятными названиями. Командная строка может быть доступна как дополнительная возможность для опытных пользователей. При этом все изменения автоматически отслеживаются и могут быть зафиксированы одной командой. Пользователь может выборочно включать или исключать файлы при коммите с помощью простых флагов.

При выполнении слияния интеграция изменений должна выполняться автоматически и единственным способом, чтобы не путать пользователя. Интеграция изменений должна учитывать конфликты файлов и локализировать их без остановки процесса.

**Локальная синхронизация**. Система может синхронизировать репозитории между устройствами по локальной сети или через съёмные носители. Возможна также интеграция с облачными хранилищами, но без обязательного центрального сервера.

Важно чтобы система выполняла синхронизацию без потери или перезаписи информации.

**Поддержка метаданных и различных типов файлов**. Система должна корректно обрабатывать текстовые документы, изображения, презентации, учитывая особенности их форматов (например, для изображений можно использовать бинарные различия, но с возможностью просмотра версий).
