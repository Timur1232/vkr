# AGENTS.md

## О репозитории

Это не код, а текстовые материалы ВКР: Obsidian-vault в `doc/`. Здесь нет сборки, тестов, линтеров и манифестов пакетов — не ищи `package.json` и не пытайся запускать проверки. Git-репозиторий: `master` -> `origin` (`github.com:Timur1232/vkr`).

Все существующие файлы, кроме `doc/by-ai/`, считаются доступными только для чтения. Изменять их можно лишь по прямому указанию пользователя; всё, что агент пишет сам, сохраняй в `doc/by-ai/`.

## Структура

- `doc/by-ai/` — единственное место, куда агент пишет свои материалы (черновики, выдержки, найденные источники). Это необработанный материал; пользователь сам переносит его в основные документы.
- `doc/Концепция решения.md` — краткая концепция разрабатываемой системы.
- `doc/Анализ предметной области.md` — основной текст главы: актуальность, обзор VCS, модель системы, целевая аудитория.
- `doc/.obsidian/` — конфиг Obsidian и сторонние плагины/темы. Не редактируй, не форматируй и не коммить изменения в `workspace.json` (это UI-состояние).
- `doc/articles/` — PDF-литература, только для чтения. Не переименовывай и не правь.
- По настройкам Obsidian новые заметки идут в `doc/incoming`, вложения — в `doc/attachments`, шаблоны — в `doc/templates`; ссылки — markdown, а не wiki.

## Работа с текстом

- Оба документа на русском; пиши по-русски и сохраняй академический стиль ВКР.
- Источники истины о замысле — эти два `.md`, но они неполные и будут переписываться. Не считай их финальной спецификацией и не «додумывай» пробелы без запроса.
- `// TODO` в тексте — намеренно оставленные места; не заполняй их молча.
- Держи единую терминологию: репозиторий, коммит, ветка, слияние (merge), локализация конфликтов, «суперпозиция» файла, уровень репозитория / уровень файла, метаинформация в корне репозитория.
- Зафиксированные проектные решения: распределённая модель без обязательного сервера, только merge (rebase не реализуется), конфликты не останавливают слияние, а порождают ветки уровня файла.

## Git

- Рабочее дерево может содержать незавершённое перемещение PDF из `doc/` в `doc/articles/` (удаления + неотслеживаемая папка). Не коммить чужие/несвязанные изменения и не делай `git add -A`; стейджи конкретные файлы.
- Без явной просьбы ничего не коммить и не пушь.
